# 3.1 Ler um teste

🔁 **Lembra da aula anterior?** Quando um teste falha, o que aparece no fim do `core:test`?

<details><summary>Ver resposta</summary>

`FAILED`, com o nome do teste, e `BUILD FAILED` no fim.

</details>

> [!IMPORTANT]
> 🎯 **Objetivo** — Ao final, você lê um teste JUnit do jogo e escreve um teste novo do mesmo jeito.

> [!NOTE]
> 💡 **Ideia** — Um teste é um `assert` com nome. Você já usou dezenas nas aulas: `assert fome == 4, "dica"`. O **JUnit** é o mesmo em Java: `assertEquals(esperado, real)`. Cada teste prepara uma criatura, faz uma coisa e confere o resultado.

## 🔮 Prever

Leia este teste do jogo. A criatura começa com vida `1.0`. Que número vai no lugar do `???`?

```java
@Test
@DisplayName("dano acumula entre golpes")
void damageAccumulates() {
    Creature c = living();

    c.applyDamage(0.3f, "combate");
    c.applyDamage(0.3f, "combate");

    assertEquals(???, c.health, 1e-6f);
}
```

`living()` é uma função do próprio arquivo (linha 14): cria uma criatura viva.

## ▶️ Rodar

No Git Bash, na pasta do projeto: `./gradlew core:test --tests "*CreatureTest*"`. O arquivo inteiro está em [CreatureTest.java](https://github.com/Lhordrixon/mundo-vivo/blob/main/core/src/test/java/com/emannuel/mundovivo/sim/creature/CreatureTest.java#L32-L41).

## 🔍 Investigar

1. O que o `@Test` faz?
2. Para que serve o terceiro número, `1e-6f`?
3. Que três partes o teste tem? Os rótulos do Nível 0 ajudam.

## ✏️ Mudar

Troque o segundo golpe para `0.5f`. Qual número o `assertEquals` precisa esperar agora? Mude, rode e depois volte os dois números.

## 🧩 Montar

No fim do arquivo, antes da última `}`, escreva um teste novo: três golpes de `0.4f` matam a criatura. Use `assertTrue` no último golpe, que devolve `true` quando mata.

> [!WARNING]
> ⚠️ **Armadilha** — Número quebrado quase nunca é exato: 0.3 + 0.3 não dá 0.6 certinho. Por isso o `assertEquals` com `float` leva uma tolerância. Sem ela, o teste falha por um fio.

> [!TIP]
> ✅ **Como saber que acertou** — `core:test` termina em `BUILD SUCCESSFUL` com o seu teste novo rodando junto.

<details><summary>🔓 Resposta</summary>

**Prever:** `0.4f`, porque 1 − 0.3 − 0.3 = 0.4.

**Investigar**

1. Marca o método como teste: o JUnit roda ele sozinho.
2. É a tolerância: aceita uma diferença minúscula por causa do número quebrado.
3. Preparar (`living()`), Atualizar (`applyDamage`) e Conferir (`assertEquals`).

**Mudar:** `0.2f`, porque 1 − 0.3 − 0.5 = 0.2.

**Montar**

```java
@Test
@DisplayName("três golpes de 0.4 matam")
void threeBlowsKill() {
    Creature c = living();
    c.applyDamage(0.4f, "combate");
    c.applyDamage(0.4f, "combate");
    assertTrue(c.applyDamage(0.4f, "combate"));
}
```

</details>
